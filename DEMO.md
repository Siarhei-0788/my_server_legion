# Демонстрационный режим (без Firebase, PostgreSQL и Redis)

Сервер `server.js` — production-вариант: Firebase Auth, PostgreSQL, Redis, FCM, coturn.
Для защиты и локальной разработки добавлен `server-dev.js`: тот же HTTP/Socket.IO-контракт,
но без внешних сервисов и с собственной авторизацией по токену.

Состояние (пользователи, токены, устройства, сообщения) сохраняется в `STATE_FILE`
и переживает перезапуск; `STATE_FILE=off` отключает сохранение. Для звонков через
мобильные сети сервер умеет выдавать TURN-учётные данные (`TURN_URLS` +
`TURN_SHARED_SECRET`, как у coturn).

Развёртывание на VPS с HTTPS — в [DEPLOY.md](DEPLOY.md).

## 1. Запустить сервер

```powershell
cd F:\Diplom\my-server
npm install          # один раз
npm run dev          # http://0.0.0.0:3000
```

Проверка: `curl http://127.0.0.1:3000/health` → `{"status":"ok","demo":true,...}`

Порт и админа можно изменить:

```powershell
$env:PORT=3100; $env:ADMIN_USERNAME='admin'; $env:ADMIN_PASSWORD='S3cretPass'; npm run dev
```

## 2. Указать адрес сервера в приложении

Меню (☰) → «Настройки сети» → адрес → «Подключиться».

| Где запущено приложение | Адрес |
|---|---|
| Эмулятор Android | `http://10.0.2.2:3000` |
| Телефон в той же Wi-Fi, что и ноутбук | `http://<IP ноутбука>:3000` |
| Внешний доступ | HTTPS-туннель (ngrok) или домен с сертификатом |

В **debug**-сборке HTTP разрешён (см. `app/src/debug/res/xml/network_security_config.xml`),
в release — только HTTPS.

## 3. Войти под администратором

Логин `admin`, пароль `123456` (или `ADMIN_PASSWORD`). Первый вход создаёт учётную запись
на сервере автоматически, потому что Firebase в демо-режиме не используется.

## 4. Выдать код бойцу

Профиль → «Сгенерировать код» → логин бойца → код (8 символов, живёт 24 часа).
Код хранится на сервере в виде записи, привязанной к логину.

## 5. Зарегистрировать второе устройство

На втором телефоне: «Регистрация» → логин, пароль, код, позывной, должность, подразделение.
Сервер проверит код, включит доступ и зарегистрирует устройство.

## Что работает в демо-режиме

- вход и регистрация по коду, роли (admin/боец);
- общий и групповые чаты, фото/видео, файлы и голосовые сообщения (до 6 МБ), геопозиции, сборы;
- список устройств и присутствие;
- звонки 1:1: сигналинг через Socket.IO, медиа — WebRTC через STUN.

## Ограничения демо-режима

- нет push (FCM): уведомления приходят, пока приложение в foreground-сервисе;
- нет TURN: звонок не установится через симметричный NAT/мобильную сеть;
- состояние в памяти: перезапуск сервера очищает пользователей, коды и сообщения;
- HTTP без TLS: только для локальной демонстрации.

## Контракт API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/auth/dev` | демо-вход `{username, passwordHash}` → `{token}` |
| POST | `/api/registration-codes` | админ создаёт код `{username, code}` |
| POST | `/api/registration-codes/verify` | боец подтверждает код, получает доступ |
| POST | `/api/register` | регистрация устройства `{phoneId, name, fcmToken?}` |
| POST | `/api/send` | сообщение `{to, text, data}` + `X-Device-ID` |
| GET | `/api/messages` | входящие/исходящие устройства (до 500) |
| GET | `/api/phones` | другие устройства |
| GET | `/api/rtc/ice-servers` | STUN/TURN для WebRTC |
| GET | `/health`, `/health/live`, `/health/ready` | проверка живости |

Socket.IO: handshake `auth: {idToken, phoneId}`, события `rtc:call`, `rtc:accept`,
`rtc:reject`, `rtc:offer`, `rtc:answer`, `rtc:ice-candidate`, `rtc:hangup`,
входящие — `rtc:incoming`, `rtc:accepted`, `rtc:rejected`, `rtc:ended`.

## Если регистрация не проходит

1. **Адрес сервера задаётся на каждом устройстве отдельно.** На втором телефоне
   откройте «Настройки сети» и введите тот же адрес, что и на первом.
2. **Сервер должен быть запущен именно как `npm run dev`** (демо-режим). `npm start`
   поднимает production-сервер, которому нужны Firebase, PostgreSQL и Redis.
3. **Телефон и ноутбук — в одной сети.** Проверка с телефона: откройте в браузере
   `http://<IP ноутбука>:3000/health` — должен вернуться JSON. Если не открывается,
   разрешите порт 3000 в брандмауэре Windows.
4. **Код должен быть выдан на тот же логин**, который вводится на втором устройстве,
   и не быть использованным (живёт 24 часа, одноразовый). После нажатия «Сгенерировать»
   приложение должно показать «Код сохранён на сервере»; если показало
   «Код НЕ отправлен на сервер» — код остался только на телефоне администратора.
5. **Пароль** — минимум 8 символов и хотя бы одна заглавная буква.
6. Диагностика на телефоне: `adb logcat -s LegiON_Register` — видно адрес сервера,
   результат входа и HTTP-код проверки кода. В консоли сервера видно строки
   `demo user created` и `access granted`.

## Переход в production

1. Поднять PostgreSQL и Redis (`docker compose up -d`), применить `migrations/001_init.sql`.
2. Создать проект Firebase, включить Email/Password и FCM, положить service account.
3. Прописать в `~/.gradle/gradle.properties` ключи `LEGION_FIREBASE_*` — клиент сам
   переключится с демо-токена на Firebase ID-token.
4. Настроить coturn (`TURN_URLS`, `TURN_SHARED_SECRET`) и HTTPS-терминацию.
